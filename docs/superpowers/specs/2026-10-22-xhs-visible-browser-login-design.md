# 小红书可见浏览器登录 MVP 设计

## 目标

让用户在小红书真实网页里完成登录与平台验证码，再由本机 MVP 尝试读取指定博主的笔记列表、显示数量并逐条归档。支持 App 分享短链和 PC 主页链接。

## 方案

用专用、可见的 Chromium 持久化浏览器上下文替换目前的二维码状态轮询。用户从 MVP 页面启动登录后，浏览器打开小红书主页；用户自行扫码、确认并完成人机验证。MVP 后端只在用户触发“检查登录”时读取该本地浏览器上下文的登录 Cookie，验证登录态后将 Cookie 写入本机隔离目录，供现有只读客户端和 yt-dlp 使用。页面不采集或显示 Cookie 明文，不尝试自动解题、代理轮换或重试平台拒绝的请求。

若平台在登录后仍拒绝笔记接口，清楚显示验证码、验证或限流状态并停止；不承诺浏览器登录一定能解锁未公开接口。

## 链接输入

- 接受 `https://www.xiaohongshu.com/user/profile/<id>` 等小红书主页链接，忽略查询参数（包括分享 token）。
- 接受 `https://xhslink.cn/o/...` 和 `xhslink.com` 短链；仅跟随有限次数的 HTTPS 跳转，并只接受最终小红书主页路径。
- 明确拒绝非 HTTPS、非小红书域名和非主页路径。

## 会话与隐私

浏览器使用 MVP 私有目录，不读取用户日常浏览器配置。Cookie 和 yt-dlp Cookie jar 仅保存在 `.tools/xhs-mvp/`，权限设为当前用户可读写。退出登录时清除 Cookie 并关闭专用浏览器上下文。终端日志、API 响应和页面状态不输出 Cookie 或分享 token。

## 验收

1. 页面可启动专用浏览器并显示等待用户完成登录/验证码的状态。
2. 用户完成登录后，点击检查能识别有效会话；若登录失败，页面给出可理解的状态。
3. 登录态成功后可继续使用现有博主笔记读取与归档流程；平台验证/限流时停止并展示原因。
4. App 短链、PC 主页链接、含查询参数的主页链接均解析到同一博主 ID；恶意域名和非主页 URL 被拒绝。
5. 本地测试覆盖链接解析、Cookie 脱敏和登录状态流程。

## 风险

小红书网页与未公开笔记接口可能变化或拒绝从浏览器会话导出的 Cookie；这时 MVP 应保持停止状态，并如实报告读取未完成。该方案用于本地可行性验证，不代表官方 API 或平台授权。
