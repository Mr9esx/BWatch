# 按平台配置下载节奏与小红书扫描减量

## 目标

让 B 站和小红书分别配置下载并发数和批次间隔，由调度器按任务所属平台应用对应策略。降低小红书自动化请求量和并发突发；平台明确返回验证或限制信号时，停止该平台后续扫描和下载。

## 方案

- 设置页按平台展示下载配置。每个平台有最大并发数、批次最小间隔和批次最大间隔。B 站迁移现有全局值；小红书默认并发数为 1、批次间隔为 10–20 分钟。当前设置只控制下载任务，不伪称为平台安全阈值。
- 调度器分别维护平台运行数和下一次可启动时间。一个平台的队列等待或冷却不改变另一个平台的节奏；暂停自动调度仍暂停所有平台。
- 小红书日常订阅扫描最多读取最新 3 页；已有本地笔记时，遇到第一条已知笔记即停止继续翻页。只合并扫描到的目录，不将部分扫描结果标记为完整。用户显式启动历史拉取时仍完整读取笔记列表，并继续使用既有历史分页节奏。超出日常扫描范围的旧笔记由历史拉取处理。
- 小红书遇到明确的 HTTP 限制或验证错误后，沿用逐次延长的平台冷却；冷却期间不启动该平台的新扫描或下载。保留用户在小红书 App 内完成验证的流程，不加入签名伪装、设备伪装或代理轮换。

## 兼容与迁移

旧状态文件中的全局下载并发和间隔用于初始化 B 站配置。小红书使用新的保守默认值，避免把原先可能偏短的全局间隔直接套用到小红书。旧字段可保留为只读迁移字段，后续保存写入新的平台配置。

## 验收

1. 设置页可分别修改并保存两个平台的并发与间隔，旧状态文件打开后配置有效。
2. 队列启动只受对应平台并发、间隔和冷却控制；两个平台各自的下一次启动时间不会互相覆盖。
3. 小红书日常扫描遇到已知笔记时停止翻页，最多读取 3 页，并将目录保持为部分状态；显式历史拉取仍可遍历完整目录。
4. 小红书限制或验证响应触发冷却，冷却期内不会启动小红书扫描或下载；B 站调度不被小红书冷却阻塞。
5. 界面说明区分下载批次间隔与订阅检查间隔，不暗示配置可保证规避平台风控。

## 限制

小红书未公布可保证账号安全的请求频率。以上配置只减少自动请求量和突发并发，不能保证不出现安全提示。若收到安全提示，应在官方 App 内处理，并暂停自动任务。
