# BiliFetch 设计

React、TypeScript、HeroUI v2、Vite 前端；Go 标准库后端；yt-dlp 负责解析与下载，FFmpeg 负责合并。面向单用户、本机及 NAS 的常驻服务。参考 biliup 的侧边导航、列表、状态标签和弹窗表单交互，不复制其代码。

## 核心流程

添加 Bilibili UID / 空间地址，或 YouTube 频道地址。首次成功检查建立已有视频基线，默认不下载历史；可明确选择最近 10 条。后续每次检查最近 50 条，发现新 ID 自动入队，重复扫描不重复下载。每个订阅支持启停、手动检查、检查间隔、清晰度。暂停订阅停止监测，不影响既有下载。

任务支持排队、下载、暂停、完成、失败，提供进度、速率、重试与取消。暂停终止 yt-dlp，恢复使用 .part 续传；合并阶段取决于 FFmpeg。重启将未完成任务重新排队。已下载视频支持本地播放和下载。

## 存储和运行

单进程使用互斥锁与原子替换 JSON 文件持久化订阅、去重集合、队列、设置、最近 500 条日志。适合个人规模；进度仅在内存更新，状态变化落盘。状态写入失败回滚并返回错误。设置限制并发 1–4、检查间隔 1–1440 分钟。下载路径由服务端环境指定，文件访问限制在根目录内。默认监听 127.0.0.1，仅接受同源修改请求；Docker 映射本机端口。

## 界面

浅色管理台，白色卡片，靛蓝重点色，固定侧栏。包含概览、订阅、任务、视频库、日志、设置，适配移动端。初始真实数据为空，提供清晰引导；单独演示模式展示示例，所有写入仅作用于演示数据。HeroUI 负责按钮、表单、弹窗、选择器和开关。错误用内联信息与通知展示。

## 验证

Go 测试覆盖基线、历史下载、去重、持久化恢复、任务状态转换、URL 限制、文件目录边界和 API 验证。使用可控 yt-dlp 可执行文件完成真实子进程集成测试，另尝试真实平台解析并如实记录外部限制。前端执行 TypeScript 检查、生产构建和浏览器关键流程检查。
